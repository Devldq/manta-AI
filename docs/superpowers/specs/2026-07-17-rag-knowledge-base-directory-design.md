# RAG 知识库目录设计

## 目标

知识库保存一个由其全部文档文件名组成的“目录”。文档上传或删除成功后增量增加或移除对应文件名，知识库列表和现有搜索可以直接使用目录定位知识库。

本功能不生成文档摘要、不调用 LLM、不新增定位接口，也不改变知识库内的向量检索和问答链路。

## 数据模型

知识库 JSON 增加字段：

```ts
interface KnowledgeBase {
  // existing fields
  directory: string[]
}
```

- 新建知识库时目录为 `[]`。
- 旧知识库缺少该字段时，读取结果兼容为 `[]`。
- 目录按上传顺序保存，一个文档对应一个目录项；同名文档保留重复文件名。

## 自动更新

目录沿用现有 `updateKnowledgeBase` 持久化，不扫描全部文档：

1. 文档上传并写入向量库后，在当前 `directory` 末尾追加该文件名。
2. 删除文档前读取其文件名；文档删除成功后，从当前 `directory` 中移除第一个相同文件名。
3. `documentCount` 和 `chunkCount` 继续沿用现有 SQLite 统计逻辑更新。

目录更新属于文档变更的一部分；如果知识库元数据持久化失败，接口返回错误，不向用户报告完整成功。目录修改始终从最新知识库对象开始，避免并发请求覆盖其他已完成的目录变更。

## 查询和界面

- `GET /api/rag/knowledge-bases` 和 `GET /api/rag/knowledge-bases/:id` 通过现有知识库对象返回 `directory`。
- 现有知识库列表搜索除名称和描述外，也匹配 `directory` 中的文件名。
- 知识库卡片展示目录中的前 3 个文件名；其余显示“还有 N 个文档”；空目录显示“暂无文档”。

## 测试

- 新建和旧知识库分别返回空目录。
- 上传后目录追加对应文件名，不扫描文档表。
- 删除后目录只移除一个对应文件名。
- 同名文档保留重复目录项，删除其中一个后仍保留另一个。
- 知识库列表能通过目录文件名搜索。
- 前端卡片展示前三项、剩余数量和空状态。

## 完成标准

1. 文档上传或删除后，知识库目录自动与当前文档列表一致。
2. 用户能在知识库列表看到目录，并通过文件名搜索到知识库。
3. 不增加 LLM 调用或新的检索链路。
